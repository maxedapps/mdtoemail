mdtoemail · 0.2.0 library API · 2026-08-18

Worker-compatible library API

mdtoemail is now a portable string-in compiler as well as a Bun CLI. One unified/remark pipeline produces a complete email HTML document plus frozen diagnostics, with no filesystem I/O on the library path, and the same packed runs in Bun and in workerd without nodejs_compat.

Tip: dashed-underlined terms and every tile are clickable. A ◆ marks load-bearing code (see ).

What changed and why

Before: only a Bun TypeScript bin existed. Conversion imported Sätteri, used Bun.escapeHTML and Buffer.byteLength, and mixed CLI I/O with rendering. There was no supported library export, and Sätteri’s WASI/Worker path is incompatible with Cloudflare Workers.

After: compileMarkdownEmail is the public root API. Config loading stays in a Bun adapter. Markdown runs through one exact-pinned unified pipeline and a project-owned sanitizer/highlighter. Package 0.2.0 ships dist/ ESM, declarations, and a built CLI.

Unchanged: TOML schema, theme tokens, GFM/frontmatter/diagnostics/highlight contracts, no sending server. Not done: human npm publish of exact 0.2.0.

The big picture

Callers pass a Markdown string. The compiler validates config, renders, wraps a table document, and returns diagnostics. The CLI is now a thin I/O adapter over that function.

Not bugs — places where a defect would break the library contract, email safety, or Worker portability.

Failure if wrong

src/compiler.ts · L22–L35 · compileMarkdownEmail 
export async function compileMarkdownEmail(
  markdown: string,
  options: CompileMarkdownEmailOptions = {},
): Promise<CompiledMarkdownEmail> {
  const config = options.config === undefined ? cloneConfig(defaultConfig) : validateResolvedConfig(options.config);
  const rendered = await renderMarkdown(markdown, config);
  const html = renderEmailDocument(rendered.html, options.title ?? "", config);
  addFinalHtmlSizeDiagnostic(html, rendered.diagnostics);
  return {
    html,
    frontmatter: toFrontmatter(rendered.frontmatter),
    diagnostics: freezeDiagnostics(rendered.diagnostics),
  };
}

Compile and pack flow

  1. Validate — omitted config is cloned; supplied config is runtime-validated.
  2. Parse — remark-parse, optional GFM and YAML/TOML frontmatter.
  3. Sanitize — raw nodes become text; allowlist, URL policy, styles.
  4. Highlight — skipped entirely when disabled; otherwise after sanitize.
  5. Wrap — table document + UTF-8 size diagnostic; return frozen diagnostics.
  6. CLI / Worker — CLI prints and may fail strict before write; Worker returns JSON of the same result.
